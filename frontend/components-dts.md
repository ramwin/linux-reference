# components.d.ts 是什么，要不要提交到 git


在 Vue 3 + TypeScript 项目里跑 `vite dev` 或 `vite build` 后，根目录（或 `src/` 下）经常会凭空多出一个 `components.d.ts`。很多人第一反应是「这文件哪来的？有用吗？要不要提交？」本文一次讲清楚。

## 它是什么

`components.d.ts` 是 [`unplugin-vue-components`](https://github.com/unplugin/unplugin-vue-components) 这个按需导入插件**自动生成**的 TypeScript 声明文件（`.d.ts`）。

`unplugin-vue-components` 的作用是：模板里直接用 `<ElButton />`、`<MyCard />`，不用手写 `import`，构建时插件自动帮你引入组件和样式。但「不用手写 import」对 TypeScript 来说是个问题——编辑器不知道 `<ElButton />` 是什么，会报 `Unknown component` 之类的类型错误。

于是插件顺手生成一份声明文件，告诉 TS「这些全局组件都存在、各自的 props 类型是什么」：

```typescript
/* eslint-disable */
// @ts-nocheck
// Generated by unplugin-vue-components
// Read more: https://github.com/vuejs/core/pull/3399
export {}

declare module 'vue' {
  export interface GlobalComponents {
    ElButton: typeof import('element-plus/es')['ElButton']
    ElDialog: typeof import('element-plus/es')['ElDialog']
    MyCard: typeof import('./src/components/MyCard.vue')['default']
    RouterLink: typeof import('vue-router')['RouterLink']
    RouterView: typeof import('vue-router')['RouterView']
  }
}
```

同类文件还有：

- `auto-imports.d.ts` — [`unplugin-auto-import`](https://github.com/unplugin/unplugin-auto-import) 生成，声明自动导入的 API（`ref`、`computed`、`pinia` 的 `storeToRefs` 等）；
- `typed-router.d.ts` — `unplugin-vue-router` 生成，类型化路由；
- `env.d.ts` / `vite-env.d.ts` — 这个不是自动生成的，是手写（或脚手架生成）的环境变量声明，别混淆。

## 有用吗

有用，但**只对开发体验有用，对构建产物无影响**：

- 给编辑器和 `vue-tsc` 提供全局组件的类型信息，模板里有自动补全和 props 类型检查；
- 它不参与运行时，删掉不影响打包结果——下次 `dev`/`build` 时插件会重新生成；
- 文件头特意加了 `@ts-nocheck`，声明它自己不参与类型检查，只作为「类型来源」被引用。

验证方式：删掉它，在 VS Code 里模板中的组件立刻报红；跑一次 `pnpm dev`，文件回来了，报错消失。

## 要不要提交到 git

**推荐提交**，这也是 unplugin-vue-components 官方 README 的建议（"It is recommended to commit this file"）。理由：

| 提交 | 不提交（加进 .gitignore） |
| --- | --- |
| CI 上跑 `vue-tsc --noEmit` 类型检查能直接过 | CI 必须先跑一次构建生成声明，否则类型检查误报 |
| 新人 clone 下来装完依赖就有完整类型提示 | 第一次打开项目满屏组件报红，要先起一次 dev server |
| diff 可追溯：升级组件库后声明变化一目了然 | 每次本地生成，无法 review 变化 |
| 偶尔有新成员加入/改名组件时产生 diff，需要随手提交 | 无此噪音 |

不提交的核心理由只有「自动生成物不该进版本库」这条洁癖，但它带来的 CI 和新成员体验成本是实打实的。社区主流做法（element-plus、vuetify 生态、vuejs 官方示例）都是**提交**。

注意两点：

1. **不要手改它**。想改内容去改插件配置（`dts` 路径、`dirs`、`resolvers`），手改会在下次构建被覆盖。
2. 团队约定好生成路径（如默认的 `components.d.ts` 或 `src/types/components.d.ts`），别让不同成员的配置生成到不同位置造成重复文件。

## 一句话总结

`components.d.ts` 是 unplugin-vue-components 自动生成的组件类型声明，只为编辑器/类型检查服务，删掉会自动重建；**建议提交到 git**，换来 CI 类型检查和新成员开箱即用的体验。
